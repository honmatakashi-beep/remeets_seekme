## 🧭 1. ReMEETs サービスコンセプトと設計思想
ReMEETsは、一般的な「無差別の男女が出会うマッチングアプリ」が抱える犯罪リスク（ストーカー、未成年売春、詐欺、なりすまし等）をシステムレベルで100%排除し、過去に確かに面識のあった者同士が安全に再会するためのクローズド・プラットフォームです。

* **想い出クイズゲート（特許水準セキュリティ）**: 
  ボトルメール（メッセージ）を発見したユーザーが中身を開くには、投函者が設定した「当事者2人にしか絶対にわからないクイズ」に完全一致（文字列一致）で正答する必要があります。無関係な第三者の侵入を物理的に完封します。
* **連絡先安全引き渡し（セキュア・ブリッジ）モデル**:
  アプリ内にメッセージ送受信空間を持たず、想い出照合と本人確認（eKYC）完了後に、合意された連絡先（LINE IDやメールアドレス等）を安全に開示・引き渡して完結する設計を採用。インターネット異性紹介事業への非該当性を確立し、監視負担・法的リスクを最小化しています。
* **青少年保護 ＆ eKYC公的認証**: 
  18歳未満（高校生を除く）の利用は規約上完全不可。ユーザー登録時の年齢申告、さらに連絡先開示手続き前の「電子的利用宣誓（法令遵守・ストーカー禁止）」および公的身分証認証を必須化しています。

# 🏗️ 第1部：動作確認前に実施する「本番インフラ・設定準備」

本番環境の構築から、各種外部APIの商用キー発行、法務文書の制定、テストデータの初期化まで、実機動作確認に入る前に完了させておくべき重要手順です。

## 🗄️ 【Stage A: データベース ＆ インフラ基盤構築】
1. **本番用マネージドRDBMSのプロビジョニング**:
   - 開発用のSQLiteから、本番運用の高可用性マネージドデータベース（Supabase PostgreSQL または Google Cloud SQL PostgreSQL）をプロビジョニングします。
2. **環境変数 `DATABASE_URL` の安全な設定**:
   - 接続パスワードを含むデータベース接続URLをソースコードに直接記述せず、サーバー環境変数（Cloud Run / Hosting）にシークレットとして設定します。
3. **初期テーブルスキーマのマイグレーション実行**:
   - Drizzle ORM等を使用し、本番の空データベースに対してテーブル（users, posts, quizzes, matches, audit_logs 等）とインデックスを一括適用します。
4. **DB自動デイリーバックアップの有効化**:
   - 万が一のデータ破損や攻撃に備え、自動デイリースナップショット（保持期間7〜14日間）を有効化します。

## ⚙️ 【Stage B: 外部API・認証・決済の商用本番キー発行 ＆ 設定】
1. **Google AI Studio / Vertex AI (Gemini API) 本番キー設定**:
   - `GEMINI_API_KEY`: 誹謗中傷・ストーカー・不当個人情報のリアルタイムAI検閲のため、従量課金を有効化した商用本番キーを設定。
2. **メール配信インフラ (Resend / SendGrid) のDNS認証 ＆ キー設定**:
   - 独自ドメインのDNS設定（SPF/DKIM/DMARC）を完了し、送信到達率を担保。`RESEND_API_KEY` および送信元アドレス（`noreply@yourdomain.com`）を設定。
3. **Stripe (決済代行インフラ) 本番加盟店契約 ＆ APIキー設定**:
   - `STRIPE_SECRET_KEY` / `VITE_STRIPE_PUBLISHABLE_KEY`: 加盟店審査を完了させ、想い出照合・連絡先開示手数料（600円〜1,200円）の決済キーを設定。
4. **Stripe Webhook エンドポイント登録 ＆ 署名シークレット設定**:
   - `STRIPE_WEBHOOK_SECRET`: `/api/stripe/webhook` を登録し、決済成功や審査落ち時の自動返金イベントを安全に受信。
5. **SNSログイン (LINE Login / Google OAuth) 本番クライアント設定**:
   - LINE Developers / Google Cloud Console にて本番ドメインの認可リダイレクトURI（`/api/auth/sns/callback` 等）を登録。
   - `LINE_CHANNEL_ID`, `LINE_CHANNEL_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` を環境変数に設定。
6. **eKYC（公的本人確認）事業者とのAPI連携設定**:
   - TRUSTDOCK / LIQUID 等の本人確認API本番キー（`EKYC_API_KEY`）を設定。

## 📝 【Stage C: 法務・特定商取引法・連絡先情報の実データ確定】
1. **特定商取引法に基づく表記の整備 (住所・電話番号対策)**:
   - バーチャルオフィス住所（東京都内等）および 050 IP電話番号を契約し、特商法ページ（`CompanyPage`）に明記。
   - 販売価格（開通手数料 600円〜1,200円 / 税込）、役務提供時期、返金ポリシーを確定。
2. **利用規約（TOS）およびプライバシーポリシー（PP）の確定**:
   - 連絡先安全引き渡し（セキュア・ブリッジ）完結モデル、SNSログイン時の取得データ範囲、eKYC身分証データの外部セキュア保管ポリシーを明文化。
3. **全法的文書の【制定日・施行日】の運用開始初日への確定・統一**:
   - 利用規約、プライバシーポリシー、ガイドライン、特商法表記の制定日・施行日を正式サービス開始日（2026年8月15日）に一括整合。

## 🧹 【Stage D: 本番データ環境の初期化 ＆ 初期シードデータ投入】
1. **開発用テストデータの完全物理消去（クリーンアップ）**:
   - 開発期間中に蓄積された不要なテストアカウント、デバッグメッセージ、検証ログを管理者ダッシュボードから安全に一括消去。
2. **情緒豊かな本番サンプルデータの一括自動生成（Seeding）**:
   - ローンチ直後の過疎感を防ぐため、自動Seeding機能（`/api/admin/production-seed`）を用いて、実在感のある日本の想い出ボトルメールや感謝レターを一括流し込み。

## 🔒 3. 運用セキュリティ ＆ 警察・司法捜査協力体制

* **刑事訴訟法第197条第2項に基づく捜査関係事項照会への対応**:
  ストーキングや事件発生時、令状に基づき「SNS認証UID」「SMS認証電話番号」「eKYC公的氏名」「IPアドレス・タイムスタンプ」「電子的宣誓同意ログ」を迅速に開示提供できる体制を維持。
* **シャドウフラグ技術による攻撃抑止**:
  悪質ストーカーや迷惑業者の投稿に対しては、送信側には成功したように擬態表示しつつ内部DBでは即時隔離する『シャドウフラグ技術』を採用。
* **不揮発性セキュリティ監査ログのエクスポート**:
  管理画面より、司法捜査提出用のタイムスタンプ付き監査ログCSVをワンクリックで安全に出力可能。
